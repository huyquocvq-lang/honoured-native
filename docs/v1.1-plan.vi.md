## 1. Tóm tắt phạm vi

### 1.1 Kiến trúc thực tế

App iOS hiện tại là **native shell (`WKWebView`) bọc web app Lovable** tại `honour-your-word.lovable.app`. Lớp native hiện chỉ gồm 7 file Swift và đảm nhiệm billing (RevenueCat) cùng một bridge message tối giản.

| Thành phần | Hiện trạng |
|---|---|
| `ios/Honoured/HonouredWebView.swift` | WKWebView + navigation policy + microphone permission |
| `ios/Honoured/NativeBridge.swift` | Bridge v1: `APP_READY`, `CHECK_ACCESS`, `IDENTIFY_USER`, `LOGOUT_USER`, `START_PURCHASE`, `RESTORE_PURCHASES` |
| `ios/Honoured/SubscriptionService.swift` | RevenueCat, entitlement `honoured_plus` |
| `ios/project.yml` | XcodeGen, **một target duy nhất**, iOS 16.0, Swift 5.9 |
| `ios/Honoured/Info.plist` | Chưa có key HealthKit, chưa có background modes |
| Entitlements | **Chưa tồn tại file nào** |

Toàn bộ UI nghiệp vụ (Contract, Progress, Journal, Calendar, Settings, Testament Timer UI) nằm ở web app — **không thuộc phạm vi tài liệu này**, xem mục 7 cho phần phụ thuộc.

### 3.1 Bridge v2 — hợp đồng message

**Nguồn chính thức: [`docs/bridge.md`](bridge.md)** — đã chốt ngày 13/09 (M1-01 xong). Không lặp lại bảng ở đây để tránh hai bản lệch nhau.

Tóm tắt các nhóm message v2 (toàn bộ v1 giữ nguyên):

| Nhóm | Web → Native | Native → Web |
|---|---|---|
| Auth session | `SET_AUTH_SESSION`, `CLEAR_AUTH_SESSION` | `AUTH_SESSION_UPDATED`, `AUTH_SESSION_INVALID` |
| HealthKit | `REQUEST_HEALTH_PERMISSION`, `GET_HEALTH_STATUS`, `QUERY_HEALTH_METRICS`, `SET_GOALS`, `SET_DAY_RESET_HOUR` | `HEALTH_PERMISSION_STATUS`, `HEALTH_METRICS`, `GOAL_REACHED`, `HEALTH_DATA_UPDATED` |
| Timer | `START_TIMER`, `CANCEL_TIMER`, `GET_TIMER_STATE` | `TIMER_STARTED`, `TIMER_COMPLETED`, `TIMER_CANCELLED`, `TIMER_STATE` |
| Nghi thức | `ACTIVITY_COMPLETED`, `SET_SOUND_ENABLED` | `NOTIFICATION_OPENED` |
| Apple | `SIGN_IN_WITH_APPLE` | `APPLE_SIGN_IN_SUCCESS`, `APPLE_SIGN_IN_FAILED` |

Những điểm khác so với bản nháp ban đầu của plan này, đã chốt trong `bridge.md`:

- **Thêm nhóm auth session** — native ghi Supabase dưới RLS nên cần user token; web đẩy xuống, native tự refresh chỉ khi chạy nền.
- **Quãng đường tách 3 metric** (`distance_walking_running`, `distance_cycling`, `distance_swimming`) — goal đạp xe không được tính bằng đi bộ. Tổng 9 identifier.
- **Đọc thêm `basal_energy`** để không phải sửa native dù Open Item #1 trả lời thế nào.
- **`GET_TIMER_STATE` + `TIMER_STARTED { endsAt }`** — web reload giữa chừng vẫn bắt lại timer; web lấy giờ từ `endsAt`, không tự `setInterval`.
- **`GOAL_REACHED` broadcast** — web giữ state contract nên native phải báo lên.
- **Web phải dùng `linkIdentity`** khi link Apple, không phải `signInWithIdToken`, nếu không mất `user_id` ẩn danh.
- Hàng đợi broadcast khi WebView chưa `APP_READY` (giới hạn 50, sống qua reload) — đã implement trong `NativeBridge.swift`.

### 3.2 Schema Supabase

```sql
-- Mẫu thô từ HealthKit, khoá chống trùng là UUID của sample
create table health_samples (
  id           uuid primary key default gen_random_uuid(),
  user_id      uuid not null references auth.users(id) on delete cascade,
  sample_uuid  uuid not null,              -- HKSample.uuid
  metric       text not null,              -- steps | distance | active_energy | heart_rate | sleep | exercise_minutes
  value        double precision not null,
  unit         text not null,
  started_at   timestamptz not null,
  ended_at     timestamptz not null,
  source_name  text,                       -- tên app/thiết bị ghi dữ liệu
  deleted_at   timestamptz,                -- soft delete khi HealthKit báo sample bị xoá
  created_at   timestamptz default now(),
  unique (user_id, sample_uuid, metric)
);
create index on health_samples (user_id, metric, started_at desc);

-- Bảng tổng hợp theo ngày để Progress tab đọc trực tiếp, không phải quét sample thô
create table health_daily (
  user_id    uuid not null,
  day        date not null,
  metric     text not null,
  total      double precision not null,
  unit       text not null,
  updated_at timestamptz default now(),
  primary key (user_id, day, metric)
);
```

- RLS: cả hai bảng chỉ cho phép `auth.uid() = user_id`.
- Native gọi RPC `upsert_health_samples(batch jsonb)` — upsert theo `on conflict (user_id, sample_uuid, metric)`, đánh dấu `deleted_at` cho UUID bị xoá.
- **`health_daily.total` KHÔNG derive từ sample thô ở server** (sửa ngày 13/09). iPhone và Apple Watch cùng ghi bước chân → cộng sample thô sẽ đếm đôi. Native tính tổng ngày bằng `HKStatisticsQuery` (tự khử trùng theo source, đúng như Health app hiển thị) rồi upsert thẳng vào `health_daily` qua RPC `upsert_health_daily(rows jsonb)`. Sample thô vẫn upload để audit và để xử lý xoá.
- **Anchor không lưu trên server.** `HKQueryAnchor` gắn với từng thiết bị → archive bằng `NSKeyedArchiver` và lưu `UserDefaults` theo key mỗi metric. Chỉ commit anchor **sau khi** batch đã upload hoặc đã ghi vào hàng đợi offline — commit sớm là mất sample nếu upload fail.
- Lần sync đầu chỉ đọc lùi 30 ngày (`initialHistoryDays`), mốc này cố định trong `UserDefaults` để mọi anchored query sau dùng cùng predicate.

### 3.3 Chiến lược chống trùng + offline

| Vấn đề | Cách xử lý |
|---|---|
| Trùng dữ liệu | `HKAnchoredObjectQuery` chỉ trả sample mới/đổi từ anchor lần trước; server thêm một lớp bảo hiểm bằng `unique (user_id, sample_uuid, metric)` |
| Sample bị xoá trong Health | Anchored query trả `HKDeletedObject` → set `deleted_at`, trừ lại vào `health_daily` |
| Mất mạng | Batch chưa gửi được ghi xuống file JSON trong Application Support; `NWPathMonitor` bắt sự kiện có mạng trở lại → gửi lại theo thứ tự, backoff luỹ thừa |
| Nhiều thiết bị | Sample UUID là duy nhất toàn cục nên hai thiết bị đọc cùng dữ liệu Health sẽ upsert vào cùng dòng, không nhân đôi |
| iPhone + Watch cùng ghi | Không cộng sample thô. Tổng ngày lấy từ `HKStatisticsQuery` trên máy (đã khử trùng theo source) — xem 3.2 |
| Qua nửa đêm / đổi múi giờ | `health_daily.day` tính theo **giờ reset hằng ngày mà user đặt trong Settings**, không phải UTC — cần web đẩy giá trị này xuống native |
